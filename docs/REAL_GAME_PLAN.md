# 真实游戏接入设计

## 目标边界

真实游戏不是第一版环境。要先建立可重复的录屏、动作、结果数据格式，且只在本地单机、得到允许的环境中使用。

## 推荐接口

```text
GameAdapter
  observe() -> Frame
  act(action, duration_ms) -> None
  reset_episode() -> None
  is_terminal() -> bool
```

`Frame` 后续可以是 RGB 图像，也可以是经过检测器提取的玩家框、Boss 框、攻击区域和 UI 状态。训练器只依赖接口，不应该知道按键或窗口坐标。

## 渐进实验

1. 录制视频，不发送输入：确认帧率、分辨率、窗口区域稳定。
2. 离线标注玩家位置、Boss 状态、受伤和死亡事件。
3. 用历史动作训练行为克隆，检查动作预测延迟。
4. 影子模式：模型只建议动作，人工执行并记录差异。
5. 受控自动化：固定场景、短回合、可随时人工接管。

## 关键风险

- 屏幕检测误差会让“无伤”奖励错误，必须保留原始帧和事件日志。
- 输入注入有延迟；动作应带持续时间，不能假设每一步瞬时完成。
- 真实 Boss 的攻击模式可能导致状态非平稳，训练/测试必须按战斗模式分层。
- 不要把“完成一次”当作唯一指标，同时报告受伤次数、动作延迟、死亡原因和泛化场景。
