# Hollow Knight RL：零基础学习说明

欢迎来到这个项目。你的最终问题可以这样描述：

> 能不能让一个智能体只看游戏画面，通过不断尝试，学会躲开 Boss 攻击，并最终无伤完成战斗？

这是一个很有挑战性的研究型问题。它不是“把一个神经网络接到游戏上”这么简单，而是四个问题叠在一起：

```text
看见什么？       -> 视觉观测：玩家、Boss、攻击范围、地形、血量
能做什么？       -> 动作空间：移动、跳跃、冲刺、攻击、等待
怎样算做好？     -> 奖励设计：存活、躲避、输出、通关、无伤
怎样越来越强？   -> 强化学习：探索、记忆经验、更新策略、反复评估
```

本项目的学习方式是：先把“看见什么”和“能做什么”简化成数字，让你理解强化学习本身；之后再逐步换成图像和真实控制。你不需要一开始就懂所有公式，但需要每一阶段都能解释自己的代码。

## 2. 先理解：强化学习到底在做什么

强化学习不是给模型一份“正确答案数据集”，而是让智能体和环境互动：

```text
智能体观察状态 s
      |
      v
选择动作 a  ------>  游戏环境执行动作
      ^                         |
      |                         v
      +------ 新状态 s' <------ 奖励 r
```

用 Boss 战来理解：

- `state`：玩家位置、Boss 位置、Boss 是否正在攻击、双方血量。
- `action`：向左、向右、冲刺、攻击、等待。
- `reward`：成功攻击得到正分，受到伤害得到大负分，通关得到额外奖励。
- `episode`：从一场战斗开始到死亡、通关或超时。
- `policy`：看到某种状态时，应该选择哪个动作的规则。

强化学习的目标不是让单步奖励最大，而是让一整场战斗的累计回报最大：

```text
G_t = r_t + gamma * r_(t+1) + gamma^2 * r_(t+2) + ...
```

`gamma` 是折扣因子。它越接近 1，智能体越在意未来的通关；它越小，智能体越偏爱眼前收益。比如“现在贪刀攻击”可能立即得分，但下一秒被 Boss 击中；无伤策略必须学会放弃危险的即时收益。

## 3. 项目阅读顺序

严格按下面顺序读，第一次不要从 DQN 或真实游戏代码开始：

### 第一步：运行项目

```powershell
cd "$HOME\Desktop\hollow-knight-rl"
$env:PYTHONPATH="src"
py -m hk_rl.train_q --episodes 3000
```

你应该看到训练局数、最近 100 局平均奖励、胜率和平均受伤次数。`runs/q_learning.json` 保存曲线数据，`checkpoints/q_table.json` 保存 Q 表。

### 第二步：阅读 `boss_env.py`

把它想象成一个非常简化的 Boss 房：横向只有 7 个位置，Boss 会移动，攻击有倒计时，玩家有 3 点生命值。

重点看：

1. `reset()`：一场新战斗如何开始。
2. `step(action)`：动作如何改变状态。
3. `reward`：哪些行为被鼓励，哪些行为被惩罚。
4. `terminated` 和 `truncated`：死亡/通关与超时的差异。
5. `_observation()`：智能体究竟能看到哪些信息。

马上做一个小练习：在纸上写出一次 `step("dash")` 前后的状态变化，并说明为什么冲刺会短暂无敌。

### 第三步：阅读 `train_q.py`

Q-learning 可以粗略理解为一本“状态-动作评分表”：

```text
Q(当前状态, 动作) = 做这个动作之后，未来大概能得到多少总收益
```

更新公式是：

```text
Q(s, a) <- Q(s, a) + alpha * [r + gamma * max Q(s', a') - Q(s, a)]
```

代码中：

- `epsilon` 控制探索：以一定概率随机尝试动作。
- `alpha = 0.15` 是学习率：每次新经验影响旧判断的程度。
- `gamma = 0.95` 是折扣因子。
- `max(values(next_state))` 表示对下一状态选择当前估计最好的动作。

注意：训练时允许犯错，评估时应该关闭随机探索。否则你无法判断学到的策略本身是否稳定。

### 第四步：阅读测试和实验记录

阅读 `tests/test_boss_env.py`，理解为什么“可复现”和“非法动作被拒绝”很重要。再打开 `docs/EXPERIMENT_LOG.md`，记录每次实验，不要只保留一次看起来最好的结果。

## 4. 分阶段学习路线

### 阶段 0：把工具跑通

目标：能够创建虚拟环境、运行模块、阅读 traceback、修改一个参数并再次运行。

需要掌握：

- PowerShell 基本命令。
- `py -m ...` 的模块运行方式。
- `venv`、`pip`、`PYTHONPATH`。
- Git 的 `status`、`diff`、`log`。

教程：

- Python 虚拟环境：<https://docs.python.org/3/library/venv.html>
- Pro Git 中文版：<https://git-scm.com/book/zh/v2>

注意：看到 `ModuleNotFoundError` 时，先确认当前 Python、虚拟环境和安装位置，不要立刻复制一条随机命令。运行 `py -c "import sys; print(sys.executable)"` 检查解释器。

### 阶段 1：本项目的 Q-learning

目标：能解释 MDP 和 Bellman 更新，并能通过实验发现奖励设计的影响。

建议实验顺序：

1. 运行 200 局，观察通常还不会稳定通关。
2. 运行 3000 局，观察策略逐渐变好。
3. 把 `epsilon` 的最小值改成 `0.0`，观察过早停止探索的后果。
4. 移除每步 `-0.01`，观察智能体是否更愿意原地拖延。
5. 把受伤惩罚从 `-3.0` 改成 `-10.0`，观察是否变得过度保守。
6. 使用 5 个不同种子，报告平均胜率而不是只报告一次胜率。

注意：训练奖励上升不等于真正学会了。智能体可能利用奖励漏洞，例如拖时间、重复攻击、依赖固定 Boss 位置。每次都要检查行为和独立评估结果。

### 阶段 2：理解标准环境

目标：熟悉 Gymnasium 的 `reset/step`、空间定义、wrapper 和 episode loop。

教程和练习：

- Gymnasium 基础教程：<https://gymnasium.farama.org/introduction/basic_usage/>
- Gymnasium 环境创建：<https://gymnasium.farama.org/introduction/create_custom_env/>
- 官方环境库：<https://gymnasium.farama.org/environments/classic_control/>

先跑 CartPole，再写一个 5x5 GridWorld。不要急着追求复杂图像环境；如果在 CartPole 上都无法解释 reward、done 和 observation，就还没有准备好接入游戏。

### 阶段 3：深度学习和 DQN

Q 表只能处理有限的离散状态。真实游戏的画面状态太多，必须用神经网络近似 Q 函数，这就进入 DQN。

按此顺序学习：

1. PyTorch tensor、`Dataset`、模型、损失函数和 optimizer。
2. 用 MLP 拟合一个简单函数。
3. 实现 replay buffer。
4. 实现 target network。
5. 在 CartPole 上训练 DQN。
6. 再考虑把本项目的状态向量换成神经网络输入。

必要教程：

- PyTorch 入门：<https://pytorch.org/tutorials/beginner/basics/intro.html>
- PyTorch 强化学习教程：<https://pytorch.org/tutorials/intermediate/reinforcement_q_learning.html>
- DQN 原论文：<https://www.nature.com/articles/nature14236>
- Stable-Baselines3 DQN：<https://stable-baselines3.readthedocs.io/en/master/modules/dqn.html>

DQN 常见不稳定原因：学习率过大、奖励尺度过大、没有 target network、经验样本高度相关、探索率下降过快。出现 loss 变成 `nan` 时，先检查输入、奖励和梯度，而不是立刻换更大的模型。

### 阶段 4：从向量到画面

目标：让智能体从帧中提取有用信息，并理解部分可观测环境。

真实画面不是完整状态：一帧可能看不出 Boss 的速度，也看不出攻击判定即将结束。因此通常需要：

- 固定截图区域和分辨率。
- 灰度化、缩放和归一化。
- 连续多帧堆叠，提供运动信息。
- 处理暂停、菜单、死亡画面和加载画面。
- 记录动作发生到画面变化之间的延迟。

必要教程：

- OpenCV Python：<https://docs.opencv.org/4.x/d6/d00/tutorial_py_root.html>
- TorchVision：<https://pytorch.org/vision/stable/index.html>
- OpenAI Gym Retro：<https://retro.readthedocs.io/en/latest/>

推荐先使用录制视频，而不是实时控制。离线数据可以反复检查，实时实验中的错误可能来自截图延迟、窗口焦点或输入丢失。

### 阶段 5：真实游戏适配

阅读 `docs/REAL_GAME_PLAN.md`，然后实现以下接口：

```text
observe() -> frame
act(action, duration_ms) -> None
reset_episode() -> None
is_terminal() -> bool
```

真实接入的正确顺序是：录屏 -> 标注 -> 离线动作预测 -> 影子模式 -> 固定短回合 -> 扩大场景。每一步都要可以人工停止，并保留原始视频、动作日志、模型版本和随机种子。

## 5. 必须理解的细节

### 奖励设计会决定学到什么

如果只奖励造成伤害，智能体可能无视自己的血量；如果只惩罚受伤，它可能站在角落什么都不做；如果通关奖励过大，训练早期可能几乎没有学习信号。奖励需要同时表达“活着、躲避、有效输出、完成目标”。

### 训练集和测试集在 RL 中也存在

固定一个 Boss 行为种子可能让策略记住攻击节奏。至少使用不同随机种子，并尽量改变初始位置、攻击时序和场景参数。报告均值和波动，而不是只贴一条最好曲线。

### 部分可观测性不是普通噪声

如果当前画面无法判断 Boss 是向左还是向右移动，智能体需要历史信息。解决方式包括帧堆叠、循环网络、显式速度估计或设计更好的观测器。不要盲目增加网络层数来解决信息缺失。

### 动作持续时间很重要

键盘按下 20ms 和按下 300ms 不是同一个动作。动作过短会产生大量无意义决策，动作过长会错过闪避窗口。训练环境中的一步应尽量对应真实控制中的一个稳定时间片。

### 先测系统，再测算法

在接入模型之前，先确认：截图帧率稳定、窗口没有失焦、动作确实发送、暂停和死亡能被检测、人工接管有效。否则“策略失败”可能其实是工程管线失败。

## 6. 遇到问题时按这个顺序排查

1. 环境是否能被随机动作稳定运行？
2. `reset(seed=x)` 是否可复现？
3. 一个手写规则策略能否赢？
4. 奖励是否有 NaN、无穷大或数量级过大？
5. 训练时是否真的在探索，评估时是否关闭探索？
6. 测试是否使用了不同随机种子？
7. 记录的胜率是否和肉眼看到的行为一致？
8. 代码改动后是否重新运行最小测试？
